them, and the evidence imported from financial institutions. That separation is
the basis for every number in the application.

## One event, several views

A grocery purchase illustrates the model:

1. The bank statement line enters Maille as a **movement**.
2. You create an **activity** named “Groceries”.
3. A **transaction** moves value from a bank account to an expense account.
4. You link the movement to the activity and attribute the matching amount.
5. A **category** groups the expense for reporting.
6. An optional **fund leg** records which purpose paid for it.

These are related records, not interchangeable labels. Keeping them separate
lets Maille answer different questions without approximation:

| Question                             | Source of truth                        |
| ------------------------------------ | -------------------------------------- |
| Where is the money?                  | Account balances                       |
| What happened?                       | Activities and transactions            |
| Does the ledger agree with the bank? | Reconciliation links                   |
| What was the money for?              | Funds                                  |
| How should the event be reported?    | Categories and projects                |
| Who ultimately owes what?            | Shared transactions and counterparties |

## Why double-entry

Every transaction names a source account, a destination account, and an amount.
The same amount leaves one side and enters the other. Maille therefore derives
balances, activity types, and reports from the same records instead of storing
separate totals that can drift apart.

Starting balances are explicit exceptions at the ledger boundary. They describe
the state when tracking begins; transactions describe every change after it.

The bookkeeping ideas behind these choices — stocks and flows, the accounting
equation, realization — are developed in
[Ledger concepts](/docs/ledger). The full list of what each action changes is
in [Actions & implications](/docs/financial/actions).
